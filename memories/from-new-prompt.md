The user wanted to understand how to build a coding-agent harness integration for Cadri, so agents can log memories into a shared database. They used the Vercel plugin as a reference. Coding harnesses take plugins. A plugin is a bundle of markdown and JSON the harness loads: skills tell the model when and how to act, commands and subagents are narrower prompts, and hooks run on their own at lifecycle points. An MCP server is the backend the model calls. The portable part across harnesses is a skill plus MCP. Hooks are per harness, and they are what capture a session even when the model never decides to write anything down.

Looking at popular Claude Code plugins showed that most of the package is markdown. Code shows up only when a hook must run (usually a shell script) or an MCP server must exist (usually TypeScript or Python, using the official MCP SDKs). The agent SDKs from Claude, Cursor, Codex, and Copilot embed a harness inside an app. They are not how you write a plugin.

For a shared memory server, Claude Code on the laptop is the MCP client and Cadri is the MCP server, exposed over HTTP. The plugin is local files that point Claude at that URL and tell it when to call. Hooks and the dashboard can use an ordinary HTTP API on the same service, because those paths do not go through the model.

Capture and summarization were split on purpose. Hooks should copy the transcript Claude already writes. Summarization should run later on the server, over stored text, not inside the user's turn and not on every message. The hook points that matter are SessionStart, Stop, PreCompact, and SessionEnd. SessionStart fires before the transcript file exists, so a read error there is normal. The full file arrives on a later hook.

The user then asked for a tracer bullet that only stores full transcripts. That produced three pieces: a Claude plugin loaded with `claude --plugin-dir ./plugin`, whose hooks POST the transcript file; a Rust Axum server with a POST and a GET for transcripts; and a small TypeScript page that lists them in a table. The transcript column pretty-prints each JSON line so the table is readable.

The user runs Claude through local Ollama, so `claude --plugin-dir` is not the command they type. Ollama only forwards arguments that come after `--`. The launch that works is `ollama launch claude --model gemma4:26b --yes -- --plugin-dir ./plugin -p "Reply with the single word pong."` That run stored a transcript from `gemma4:26b`.
