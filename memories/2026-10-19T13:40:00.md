The question was how a person gets into hosted Cadri without an admin creating them in WorkOS. Staging is `staging.cadri.io` and production is `app.cadri.io`. Each has its own WorkOS environment. Sign-in is AuthKit, which WorkOS hosts. The Rust engine exchanges the one-time code and stores the access token and refresh token in the `cadri_session` cookie. The token's `org_id` is the only organization a request can read or write. A token with no `org_id` is rejected with `403 {"error":"no_organization"}`. Until this change, self-service sign-up was off, so a new team meant an admin created the organization in the WorkOS dashboard and invited the email.

The product decision is two paths that share that same organization claim. Someone with no invite signs up in AuthKit, lands in Cadri with no organization, and types a team name. Cadri creates the WorkOS organization, adds that user as its admin, and refreshes the session so the new access token carries the new `org_id`. A teammate does not get their own organization. Any current member types the teammate's email in the Cadri app, WorkOS emails that address, and accepting the link signs them up directly into the inviter's organization. Signing up while ignoring the invite still creates a separate organization. There is no domain auto-join and no merge. A second organization and a switcher stay deferred: a session that already has an `org_id` is not given another one, and more than one existing membership is rejected rather than picking one.

That split is why the team form and the invite form live in the Cadri web UI, while the account itself stays in AuthKit. WorkOS invitations are addressed to one email. The organization id on the invitation is taken from the session token, not from the request body. The creator is the WorkOS `admin` role. Invitees get WorkOS's default member role. Cadri still does not read roles to decide who may invite. The plugin cannot show the team form. If its token has no organization, the hook tells the person to open Cadri in the browser, create the team, and run `cadri-login` again. After that, AuthKit puts the single organization on the next device token.

The WorkOS "Sign up" switch is per environment, in the authentication section of the dashboard, and there is no API for it. It was turned on for both Staging and Production. Staging's AuthKit page offers "Sign up". Production's sign-up screen asks for a first name, last name, and email. Verified domains and domain auto-join stay off. The team form is still only on the `self-service-signup` branch, so completing that screen on the deployed app leaves a user with no organization.
