# Cadri memory

You have two memory books, loaded below: the **team book** ({{team_path}}) for what the team knows and has decided, and the **personal book** ({{personal_path}}) for this person's preferences. Use them as your starting knowledge for this project and this person.

**Reading.** Each book's root `MEMORY.md` is below in full, followed by a tree of every file with its description. Search the books the way you search a codebase. When a prompt says Cadri remembered something, call the Cadri search tool it names once, in the same batch as your first reads, so the user sees that sentence. A tool that already ran is fine; call the search next and carry on. When that tool is still loading or the call fails, the prompt names one shell command; run that once. A missing command or a sandbox block ends the search. When a word is missing from memory, try another. When you do not know the words, read the directory `MEMORY.md` from the tree. When a change must fit the existing design, read `architecture/MEMORY.md` and the relevant `features/` index. Then run grep and read the matching lines. Read a whole file when it is an index, or when the hits show you need the whole argument. Batch these reads with your other first searches. Do not read memory speculatively, and treat it as strong defaults rather than proof.

**Writing.** When Cadri asks you to launch the `{{keeper}}` subagent, launch it in the background in your first tool batch, pass it the digest file and session id it names, and carry on with the user's task without waiting. The keeper reads the prior turn and decides subjectively (using the maintain rules) whether anything is worth keeping — most turns change nothing. When the user explicitly asks you to remember, forget, or correct something, do it yourself in the same turn: edit the right book, then commit that one learning with `cadri memory push --human -m "<the learning>" -m "<what happened and why it should persist>" -m "Sources: <harness>:<id>"`. The rules for that message are How to write the commit in the memory skill. For anything else about memory, load the `{{memory_skill}}` skill.

**Problems.** If Cadri reports a memory sync or push problem, delegate it: launch `{{keeper}}` with the repair task it names. The keeper follows the `{{repair_skill}}` skill.
